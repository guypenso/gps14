## הפעלה לאחר אישור מפורש בלבד

1. להשלים את בדיקת המסד, לקבל את תחילת מחזור RentCast בפועל כולל שעה ואזור זמן, ואת השימוש המעודכן. לאשר במפורש עד 200 ניסיונות ועד $30 בחריגות Developer למחזור. יש לרכז את השימוש בחשבון במערכת זו או לחשב גם שימוש חיצוני; הקוד אינו יכול לחסום קריאות שנעשות מחוץ למערכת.
2. בשירות `rentalsourcing-daily` להגדיר את הערכים הבאים, תוך השארת האיסור על שימוש ועל מיילים:

```dotenv
ENABLE_RENTCAST=false
ENABLE_EMAIL=false
EMAIL_APPROVAL_ID=
API_APPROVAL_MODE=billing_cycle
API_APPROVAL_ID=rentalsourcing-daily-200
APPROVED_API_REQUESTS=200
MAX_API_REQUESTS_PER_MONTH=200
MAX_API_REQUESTS_PER_DAY=8
MAX_API_REQUESTS_PER_RUN=8
LISTING_REQUESTS_PER_DAY=1
LISTING_LIMIT=500
TAX_CACHE_HOURS=720
NEGATIVE_TAX_CACHE_HOURS=168
NETWORK_RETRIES=1
```

בנוסף חובה להגדיר `BILLING_CYCLE_ANCHOR` לתחילת המחזור האמיתית בפורמט ISO עם אזור זמן, ו־`BILLING_USAGE_BASELINE=5` רק אם השימוש בעת ההפעלה עדיין 5. אין להדביק תאריך דוגמה משוער. לאחר חידוש עתידי, המכסה מתחדשת לפי אותו עוגן; חודש קצר לא משנה את היום המקורי. שינוי מזהה אישור אינו מאפס שימוש שנשמר למחזור. שמונה ניסיונות ביום הם תקרה; הקוד מקצה פחות לפי היתרה ומספר הימים שנותרו ושומר קריאות לסריקות עתידיות.

אם הסריקה דורשת יותר מעמוד אחד ביום, לעדכן `LISTING_REQUESTS_PER_DAY` ולחשב מחדש את התחזית לפני ההפעלה.

3. רק לאחר האישור ושמירת ההגדרות להגדיר `ENABLE_RENTCAST=true`. להשאיר Cron ב־`0 12,13 * * *` ב־UTC; הקוד מאפשר רק את החלון התואם ל־08:00 `America/New_York`, כולל שעון קיץ. התור וההתקדמות נשמרים במסד. אין לשנות DB או מסלול Render.

מיילים נשארים כבויים. בעתיד הם דורשים בנפרד Resend עם שולח מאומת, נמען, `RESEND_API_KEY`, מזהה אישור `EMAIL_APPROVAL_ID` ואישור מפורש לפני `ENABLE_EMAIL=true`. מפתחות נשמרים בפרטיות ב־Render, ולא במאגר או בצ׳אט.
