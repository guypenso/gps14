# הפעלת RentalSourcing — המערכת הקיימת

הקוד כולל דשבורד Web פרטי, סריקה מתוזמנת, PostgreSQL, Cache, אימות מסים ומייל יומי.
המערכת נבדקה מקומית; לא נפרסה בענן ולא השלימה עדיין בדיקת נתוני מודעות חיה מוצלחת.
מצב הבדיקה החיה מתועד ב־LIVE_ACCEPTANCE_HE.md. אין צורך להתקין תוכנה במחשבך.

## עלות התצורה המוכנה

| רכיב | עלות חודשית בסיסית משוערת |
|---|---:|
| Render Web Starter לדשבורד | $7 |
| PostgreSQL קטן | $6 |
| 5GB אחסון PostgreSQL | $1.50 |
| Cron יחיד לסריקה | לפחות $1 |
| Resend בהיקף ההתחלתי | $0 |
| סך האירוח והמייל | כ־$15.50 |

RentCast Developer כולל 50 קריאות בחודש. בתצורת ניסיון של עד 40 ניסיונות בחלון
מתגלגל שמרני של 32 ימים, ובהיעדר שימוש נוסף באותו חשבון, עלות הנתונים יכולה להישאר $0.
זו מכסה מצומצמת: סריקה יומית דורשת בערך 30–31 קריאות מודעות ועוד השלמות מס, ולכן לא
כל מועמד יקבל מס מדי יום. Cache ועדיפות להורדות מחיר מצמצמים את הצורך. חסר מידע נשאר Pending.
אין התחייבות לכיסוי מלא במסגרת $15–30. הגדלת שימוש מחוץ למכסה הכלולה מחייבת אישור נפרד.

האומדן לפני מסים, דומיין אם נדרש, חריגות תעבורה ומשאבים או שינויי מחיר. המסך ב־Render
הוא הקובע לפני אישור החיוב. מחירון: https://render.com/pricing ; https://www.rentcast.io/api .

## הפעולות שלך, בסדר

1. לברר בחשבון RentCast שהמנוי API פעיל ושהמפתח מורשה ל־Sale Listings. הבדיקה האחרונה
   נדחתה עם Forbidden. ארבעת הניסיונות כבר אושרו; אין צורך לאשר אותם שוב, אבל אין לבצע
   retry חסר אבחנה. שלושה ניסיונות נותרו, והם מיועדים להשלמות של נכסים שנמצאו.
2. בסביבת Codex, אם רוצים להשלים את בדיקת המיקום כאן, לאפשר services1.arcgis.com
   ברשימת הרשת. זו הורדה ציבורית של גבול עיר. לחלופין ההורדה מוכנה לבנייה ב־Render.
3. לאשר יצירת שירותי Render בעלות הבסיס המוצגת, כ־$15.50 בחודש. טרם ניתנה התחייבות
   כספית וטרם נוצרו משאבים. לחבר את guypenso/gps14 ולבחור Blueprint מתוך render.yaml.
4. לפני Apply לבדוק: Web אחד, Cron אחד ו־PostgreSQL אחד, כולם באותו אזור. ברירות המחדל
   מכבות RentCast ומיילים ומאשרות 0 קריאות. יצירת המשאבים עצמה מתחילה חיוב אירוח.
5. בשירות הסריקה בלבד להגדיר RENTCAST_API_KEY, RESEND_API_KEY, EMAIL_FROM ו־EMAIL_TO
   במסך Environment הפרטי. כתובת היעד כבר נמסרה; לא לשמור אותה בקוד הציבורי.
   לאמת שולח/דומיין ב־Resend. לא להדביק מפתחות בצ׳אט.
6. Render מחבר DATABASE_URL לשני השירותים ומייצר DASHBOARD_PASSWORD לשירות Web.
   משתמש הכניסה הוא owner; את הסיסמה קוראים באופן פרטי מ־Environment של Web.
7. לאחר בנייה מוצלחת לפתוח את כתובת onrender.com של שירות Web. להיכנס בסיסמה.
   /healthz בודק DB ללא חשיפת נתונים; /readyz דורש כניסה ומוודא גם את גבול העיר.
8. להשלים בדיקת RentCast חיה לאחר פתרון Forbidden, עם המכסה שנותרה ולא יותר מהאישור.
   הפקודה להכנת/ביצוע בדיקת 100 המודעות קיימת ב־python -m rentalsourcing.poc.
   ברירת המחדל שלה מציגה תוכנית בלבד; --execute דורש אישור חד־פעמי שמוגבל ל־1–4.
9. לבדוק את המייל השמור בדשבורד במצב תצוגה בלבד. רק אחרי בדיקת נתונים אמיתיים, הגדרת
   השולח ואישור שליחה להפעיל ENABLE_EMAIL=true. אין שליחת מייל מתוך כפתורי הדשבורד.
10. לפני הפעלה קבועה לאשר בנפרד מכסה מתמשכת. API_APPROVAL_MODE=one_time מגביל אישור
    מצטבר שאינו מתחדש. rolling_32_days מאפשר, רק באישור מפורש, עד APPROVED_API_REQUESTS
    בכל חלון שמרני של 32 תאריכי UTC. המכסות היומית, למחזור ולריצה עדיין חלות בנוסף.
    לדוגמה cap=40 יכול לשמור על שימוש מצומצם בתוך 50 הקריאות הכלולות, אם אין משתמשים
    אחרים בחשבון. אין מנגנון שיכול לדעת על צריכה חיצונית ללא גישה לחשבון הספק.
11. להפעיל ENABLE_RENTCAST=true רק עם אישור מכסה מתאים. יעד הסריקה הוא 08:00
    America/New_York, בקיץ ובחורף. שני חלונות UTC מפעילים רק את השעה המתאימה.
    בדיקת POC חד־פעמית אינה אישור לקריאות יומיות נוספות מעבר לארבע שכבר אושרו.

## שימוש שוטף

- הדשבורד קורא רק את הנתונים השמורים. רענון אינו צורך API או שולח הודעות.
- התצוגה מראה את סיבת הפסילה או המידע החסר, מקור ושנת המס, חישוב +$100 ומועדי האימות.
- רק נכסים שעברו את כל התנאים מסומנים מאומתים; נתון ישן או גבול חסר מורידים את התצוגה להמתנה.
- Coverage נשאר ״לא נמדד״ עד שיש מדגם השוואה מורשה; אין טענה לכיסוי מלא.
- סריקה ידנית: python -m rentalsourcing.cloud. המשך לאחר כשל: --resume JOB_ID.
- PostgreSQL שומר משימות, נתונים ומכסה בין ריצות. outbox מונע שליחה כפולה לאותו אירוע.
- הורדת מחיר חדשה עשויה לייצר התראה חדשה; אותה הורדה אינה נשלחת שוב. אחרי המייל היומי
  האירוע ממתין למייל הבא ולא גורם לעוד מייל באותו יום.
- כשל מייל לא ודאי מאפשר --retry-email בתוך 23 שעות עם אותו מפתח; לאחר מכן נדרשת בדיקה
  ב־Resend ו־--reconcile-email עם מזהה אמיתי. אין לשחזר DB ישן ולשלוח מחדש בלי לבדוק את outbox.
- לכבות קריאות ומיילים: ENABLE_RENTCAST=false ו־ENABLE_EMAIL=false. כדי לעצור חיובי אירוח,
  יש לעצור/למחוק את המשאבים ב־Render לאחר גיבוי; כיבוי הקריאות לבדו אינו מבטל חיובי DB/Web.

במצב rolling_32_days התזמון שומר מקום לקריאת מודעות אחת בכל יום לפני שהוא מקצה
קריאות נוספות למס. נבדקו 95 ימי סריקה רצופים עם מכסה 40, כולל מעבר בין חודשים,
מבלי לחרוג מ־40 ניסיונות בחלון. אם נדרשים יותר מעמוד מודעות אחד ביום או יש שימוש
ידני/חיצוני נוסף, עדיין ייתכן מחסור ותופיע התרעה; אין הבטחה לסריקה מלאה בתקציב המצומצם.
